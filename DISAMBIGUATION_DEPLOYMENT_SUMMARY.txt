================================================================================
  PROBLEM RESOLVED
================================================================================

ISSUE: Some API keys were being misclassified as Philippine IDs
- AWS keys (AKIA/ASIA) being flagged as PhilID or UMID
- Twilio keys (AC/SK) being flagged as PhilID
- Generic 12-digit API keys matching UMID patterns (4-7-1)
- Generic 7-digit API keys matching PRC patterns

ROOT CAUSE: Overlapping pattern spaces between:
- API keys (often numeric-only formats)
- Philippine IDs (structured numeric formats)
- No disambiguation logic to differentiate them

IMPACT: Medium risk - reduced accuracy in pattern classification

================================================================================
  SOLUTION IMPLEMENTED
================================================================================

1. NEW FUNCTION: isLikelyApiKey(rawMatch, fullText)
   Location: patterns.js (after shannonEntropy function)
   Purpose: Determine if a match is likely an API key vs Philippine ID
   Signals Checked:
     - Vendor-specific prefixes (AKIA, ASIA, AC, SK, ghp_, etc.)
     - API context keywords (api_key=, secret=, token=)
     - Entropy levels (API keys > 3.0 bits/char)
     - Character variety (mixed alphanumeric vs pure digits)

2. UPDATED VALIDATORS: 
   - structuralValidatePHID_UMID()
   - structuralValidatePHID_PRC()
   Changes: Added early exit if isLikelyApiKey(raw) returns true

3. UPDATED PATTERNS:
   - ph_id_umid regex: Added negative lookahead for API prefixes
   - ph_id_philid regex: Added negative lookahead for API prefixes
   - ph_id_prc regex: Added negative lookahead for API prefixes

================================================================================
  DETECTION PRIORITY (NEW)
================================================================================

Disambiguation now follows this priority:
1. API Key Prefix Check (strongest signal)
   - AKIA, ASIA, sk-, ghp_, AC, SK, etc.
   
2. API Context Check
   - Surrounded by api_key=, secret=, token=
   
3. Philippine ID Format Check
   - Matches 4-7-1, 2-7-1, 7-digit, 4-4-4-4 patterns
   
4. Entropy Analysis
   - API keys: typically 3.0+ bits/char
   - Philippine IDs: typically 2-3 bits/char
   
5. Character Variety
   - API keys: mixed alphanumeric, special chars
   - Philippine IDs: mostly digits
